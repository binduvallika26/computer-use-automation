# Architecture

The system is a single Python process with five boundaries: planner, surface, policy, executor, and evidence sink. The planner observes a live browser and chooses one typed action. The policy validates every action before execution. Only a verified success emits a capability. Replay imports the executor and artifact models, never the planner or model SDK. The CLI is the minimal invocation boundary; callers can also use `replay(capability, inputs, ...)` directly.

Playwright drives a framed, table-based local application through visible labels and accessibility roles. The target has no business API. A reviewed control catalog makes perception deliberately narrow: the model sees which permitted controls exist and are enabled, not raw page content or account values. This requires initial application mapping but prevents page instructions and arbitrary selectors from expanding authority. It discovers the order of the workflow, not an unrestricted application's entire control vocabulary. Python/Pydantic keeps the runtime and reviewable contracts small. A separate process or queue would add operational complexity without improving this single-session demonstration.

# Artifact schema

A capability has `schema_version`, a name and version, vendor/app compatibility, entry path, typed inputs and outputs, ordered steps, and an independent success target. Each step has a closed action enum and target descriptor (role, label or exact visible text, optionally scoped to a named frame). Fill actions require a declared `input_ref`; read actions require a declared `output_ref`. No literal fill values, credentials, goal prose, model transcript or arbitrary executable code are valid fields. Extra fields and unsupported schema versions are rejected. Every declared output must be extracted exactly once. Money is a decimal string, never a float.

The artifact expresses the flow; the operator-owned policy expresses authority and known runtime conditions. A saved artifact cannot widen domains, action permissions, risk classifications, the success condition or the input/output contract. JSON is intentionally verbose enough to review and diff. `examples/capability.schema.json` is generated from the same runtime types. Version approval/signatures are a production extension, not an implied security property of a JSON file.

# Determinism & error handling

Replay follows the recorded steps in order using exact role/label/text locators, named frame scope and uniqueness checks. It never selects the first of multiple matches or asks a model to repair a locator. Playwright waits for actionability; known loading indicators receive a bounded wait rather than repeated clicks. A known maintenance notice has one explicitly reviewed dismissal. Unknown dialogs are dismissed conservatively and stop the run. Route violations, ambiguous controls, permission denial, expired sessions and application errors are explicit failure codes. Inputs are validated before navigation.

Results distinguish success with typed outputs, expected business outcomes (`not_found`, validation errors), and failures with step, expected state, observed code and run ID. Output data is returned in memory and omitted from persisted results. Checkpoint verification and completeness of extracted outputs are independent of the model's `done` assertion. Logs record action kind, reviewed control index and rationale category, avoiding raw exception messages. Failure evidence adds a structural snapshot of match counts, visibility, enablement and known conditions.

Determinism means identical control flow and targeting rules, not an assumption that account balances or network timing never change. There is no blanket click retry. A failure before the pending action may resume after a human clears the obstruction; an uncertain action outcome stops and requires reconciliation. Max steps, provider timeout, per-control waits and an execution deadline bound automated work. Interactive operator/stdin waits are deliberately outside a strict wall-clock SLA.

# Heterogeneity & multi-tenant

The seam is `observe / act / visible / open`, with ownership and evidence hooks. The core engine currently uses browser-specific bounded waiting and checks, so a new adapter also needs those hooks or a small protocol expansion; desktop support is not claimed. A legacy-web adapter can map logical controls into frame paths and accessibility labels. An OS accessibility adapter could resolve the same logical role/name contract to UI Automation controls. An image/OCR adapter would need explicit anchor templates, confidence thresholds, viewport calibration and versioned assets; raw coordinate replay is intentionally not a fallback.

At scale, store vendor capability versions separately from tenant bindings: institution origin, app build, reviewed locator overrides, credential references and narrowed policy. Never duplicate secrets into the base capability. Validate overrides against a base contract, use immutable digests and approval, and run tenant canaries against a synthetic account before promotion. A tenant cannot broaden the base permission set. Match ambiguity, missing checkpoints and incompatible version metadata should quarantine that tenant/version and create a repair request. Queue workers by tenant with isolated browser contexts, short-lived credentials, leases and per-app concurrency limits. None of that infrastructure is needed to prove this execution path.

# Escalation & handoff

The local terminal routes an intervention carrying a run ID, step, failure code and saved structural state. In headed mode it cedes the same browser to the operator, changes ownership to `human`, and blocks automated actions. The human resolves the obstruction and explicitly signals `resume` or `abort`. Event capture records click/input kinds plus a catalog index, never typed content. It records before/after control states and restores ownership in a `finally` block. Policy and runtime guards run again before the pending action. A simulated operator test proves page identity is preserved and the remaining steps complete; it is labeled as simulation, not a human session.

The minimal capture supports the included same-document, framed sandbox. Full-document navigation during handoff can replace capture listeners; a production operator channel needs context-level instrumentation, authenticated operators, lease fencing, disconnect timeouts and tamper-resistant audit storage. A terminal and visible browser are enough to make the pause/control/resume mechanism real without implementing a remote co-browsing console. Risky controls are blocked rather than implicitly approved by `resume`.

# Safety

Policy is explicit, configurable, and operator-owned. Exact origins and paths are checked at navigation and network-request boundaries, including frame/subresource requests; query strings, credentials in URLs, non-GET requests, popups and WebSockets are blocked. Downloads are canceled. Only reviewed controls and actions are executable. The synthetic account-close button is classified irreversible and blocked, irrespective of model intent. This read-only capability does not need a transaction approval mechanism.

Persistence follows data minimization: input values, extracted balances, raw model prose and page text are absent from artifacts/logs. Perception uses reviewed static labels. Failure snapshots are structural instead of screenshots that might expose PII. Goals should reference parameter names; supplied input values are removed from the goal before model transmission. Arbitrary sensitive prose in a goal is not fully redacted, so real deployments must validate/redact upstream and configure their model data policy. `store=False` is set for provider calls, but this is not a claim about all provider retention.

The sandbox and policy files are trusted. A control allowlist is not a security boundary against a compromised application: permitted GET handlers may have side effects, and a control's semantics can change. Production needs an isolated worker, network proxy, narrowly scoped service identity, controlled target releases and an authenticated policy/artifact registry. There is no claim of regulatory compliance.

# Cuts

Implemented: real UI discovery via an external model host, a provider API adapter, typed artifacts, deterministic replay, business/recoverable/hard outcomes, guardrails, redacted evidence and same-session handoff. Cut: unrestricted visual discovery, desktop automation, tenant infrastructure, remote console, transaction execution and durable recovery across process crashes. These cuts preserve a small verifiable core.

Verification limitation: the bundled successful discovery was driven by the Codex assistant through stdin, not this application's OpenAI API adapter. No API credential was available; a genuine API-backed evidence run remains necessary for the assignment's stated provider-access expectation. The repository does not relabel a fixture as an LLM run or claim a simulated operator is human. Next work is that API run, then navigation-safe handoff capture, stronger artifact approval and a second vendor version to test specialization.
